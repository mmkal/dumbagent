# TUI UI Grill Notes

## Q1: Is this a terminal emulator in the browser or a semantic browser adapter?

Recommended answer: It is a semantic browser adapter backed by a terminal emulator model. xterm-headless is the canonical screen; semantic sections are derived and allowed to be wrong without breaking usability because the raw terminal view remains available.

## Q2: Should input try to click/type into detected boxes?

Recommended answer: Not in the first pass. Generic TUIs do not expose focus or widget identity through terminal output. Use a separate composer plus raw key/chord controls, and leave click-to-focus as future app-specific behavior.

## Q3: Should this reuse xyz wholesale?

Recommended answer: Reuse the ideas, not the tmux architecture. xyz already proves browser session management, xterm-headless rendering, and chord controls. TUI UI should use Bun PTY directly because the user explicitly wants the better Bun PTY story.

## Q4: What makes the first implementation valuable?

Recommended answer: A vertical slice where fakeagent-backed OpenCode runs in a PTY, appears in a browser as sections instead of only a terminal canvas, accepts prompts from the browser, and has tests that guard that behavior.
