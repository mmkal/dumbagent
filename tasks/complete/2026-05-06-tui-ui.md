# TUI UI

Status summary: Done for the first vertical slice. The project now has a Bun PTY server, browser launcher/session UI, semantic terminal screen extraction, xterm HTML fallback, separate composer/key input, fakeagent-backed OpenCode support, and parser plus Playwright integration coverage. The main missing pieces are persistence, app-specific semantic plugins, mobile tuning, and a real ghui pass.

## Checklist

- [x] Create a Bun project with a local CLI/server entrypoint. _Implemented in `cli.ts` with `bun run cli.ts [--port n] [--fakeagent opencode] [command...]` and package scripts._
- [x] Run arbitrary commands as PTY-backed managed sessions. _Implemented with `Bun.spawn(..., { terminal })` in `cli.ts`; sessions are in memory for this pass._
- [x] Capture PTY output into a terminal screen using xterm-headless. _Implemented with `@xterm/headless` and `SerializeAddon` in each runtime session._
- [x] Derive a semantic screen with detected sections from box drawing characters and contiguous text blocks. _Implemented in `src/semantic-screen.ts` with box, prompt, status, command, tool, list, and plain section heuristics._
- [x] Serve a browser UI that renders semantic sections as HTML divs and keeps a raw terminal fallback view. _Implemented in `client/app.ts` and `client/styles.css` with `HTML` and `TTY` renderer toggles._
- [x] Provide separate browser input plus common raw key/chord controls. _Implemented with a composer and key buttons for Esc, Tab, arrows, and Ctrl-C._
- [x] Add fakeagent-backed OpenCode support for local testing. _Implemented via the `Fake OpenCode` preset and `--fakeagent opencode`, with OpenCode auto-update/model-fetch behavior disabled for the test environment._
- [x] Add Playwright coverage for session launch, semantic rendering, input, and OpenCode via fakeagent when available. _Implemented in `spec/tuiui.spec.ts`; includes fake raw-mode TUI, UTF-8 split output, key send, and fakeagent OpenCode._
- [x] Verify typecheck and tests. _Verified with `bun run typecheck` and `bun run test`._

## Assumptions and Guesses

- [guess: current scope] Persistence is not required for the first one-shot implementation; managed sessions can be in memory.
- [guess: product direction] The semantic view should default on, with terminal fallback one click away, because the translation layer is the differentiator.
- [guess: input] Generic input should use a separate composer because a terminal screen does not reveal enough focus semantics to safely target arbitrary fields.
- [guess: OpenCode] OpenCode needs a special submit path that writes text, then LF, then CR, matching the existing fakeagent helper behavior.

## Out of Scope for This Pass

- Mobile-specific layout.
- SQLite persistence.
- Full app-specific semantic plugins.
- ghui support.

## Implementation Notes

- The repo is not a git repository, so the `grill-you` worktree and commit steps were intentionally not applied.
- OpenCode's installed binary exposes `OPENCODE_DISABLE_AUTOUPDATE`; the fakeagent preset sets it so the updater prompt does not intercept tests.
- PTY output decoding uses `StringDecoder` so split UTF-8 chunks do not produce replacement characters.
